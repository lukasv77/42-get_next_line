# get_next_line

## Description

`get_next_line` is a function that reads a file descriptor line by line. Each call returns
the next line from the given file descriptor, including the trailing `\n` character (except
at EOF when the file does not end with a newline). When there is nothing left to read or
an error occurs, the function returns `NULL`.

The project introduces the concept of **static variables** in C, which are used to persist
data between successive function calls without relying on global state. The buffer size
used by `read()` is defined at compile time via the `-D BUFFER_SIZE=n` flag, making the
function adaptable to different memory constraints.

## Instructions

### Compilation

```sh
cc -Wall -Wextra -Werror -D BUFFER_SIZE=42 get_next_line.c get_next_line_utils.c main.c -o get_next_line
```

The `BUFFER_SIZE` macro can be set to any positive integer:

```sh
cc -Wall -Wextra -Werror -D BUFFER_SIZE=1 get_next_line.c get_next_line_utils.c main.c -o get_next_line
```

Compilation works both with and without the `-D BUFFER_SIZE` flag (defaults to `42`).

### Execution

```sh
./get_next_line
```

The included `main.c` runs tests on files located in the `tests/` directory.

## Algorithm

### Overview

The function maintains two static variables between calls:

- **`buffer[BUFFER_SIZE + 1]`** — the raw data read from the file descriptor.
- **`ptr`** — a pointer tracking the current position within the buffer. When `ptr == buffer`,
  the buffer has been fully consumed and a new `read()` is needed. When `ptr` points
  somewhere inside `buffer` (past a newline), leftover data from the previous call is
  still available.

### Step-by-step flow

1. **Leftover detection** — if `ptr` is `NULL` or points to `'\0'`, reset it to `buffer`.
   If `ptr != buffer`, there is unprocessed data left from the previous call (it was cut
   off mid-read after a `'\n'`). Process it immediately without calling `read()`.

2. **Read loop** — while `ptr == buffer` (i.e., the buffer is empty or fully consumed):
   - Call `read(fd, buffer, BUFFER_SIZE)`.
   - On error (`< 0`): return `NULL`.
   - On EOF (`0`): return the accumulated line, or `NULL` if nothing was read.
   - Null-terminate the buffer at `buffer[bytes_read]`.

3. **Chunk extraction** — `ft_addchunk()` calls `ft_chunkdup()` to copy from `ptr` up to
   the next `'\n'` (or `'\0'`) and appends the chunk to a linked list. If a `'\n'` was
   found, advance `ptr` past it for the next call; otherwise, reset `ptr = buffer` to
   trigger a new read on the next iteration of the read loop.

4. **Line assembly** — `ft_lststr()` walks the linked list, calculates total length,
   allocates a single string, and copies all chunks into it via `ft_mvcontent()`, freeing
   the list nodes on the fly.

### Justification

- **Linked list for chunks**: Since `read()` may not return a full line (the buffer may
  be smaller than the line, or a newline may span across read boundaries), individual
  chunks are accumulated in a linked list. Only at the end, when a full line is assembled,
  is a single contiguous string allocated and returned. This avoids resizing buffers
  repeatedly.

- **Static buffer with offset pointer**: Using a single static buffer and an offset
  pointer (`ptr`) instead of copying leftover data into a separate string avoids extra
  memory allocations. The pointer simply advances within the static buffer, tracking
  which part has already been returned.

- **Helper function `ft_addchunk`**: Extracted to keep `get_next_line` under 25 lines
  (Norm requirement) while avoiding the forbidden `for`, ternaries, and multi-statement
  lines. It encapsulates the repeated pattern "copy chunk → check for newline → advance
  pointer".

- **Early error handling**: `bytes_read < 0` is checked **before** null-terminating the
  buffer, preventing an out-of-bounds write on read error.
